# Balance Pass Wave 2 — OW Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land OW's whole share of the balance pass — one new card **with its
effect already wired**, four cards re-costed or re-worded, and one seed-time
patch retired into the source it was patching.

**Architecture:** Five of the six changes are seed data, guarded by
`supabase/seed/balance/ow.balance.test.ts` — the per-faction file Wave 0 created
so five branches never edit one guard. The sixth is a new registry id,
`brandistockOnDeath`, which shares Halberd's *implementation closure* and
deliberately does **not** share its *name* (spec R-6). Bulwark's rewrite drops a
meta key and so orphans `bulwarkOnPlay`, which stays registered with a written
justification. Rook's `vehicleType` moves from a seed-time patch table into the
card, so the source stops lying and the patch table shrinks by one.

**Tech Stack:** TypeScript (strict), Vitest, React 19 + Tailwind v4, TanStack
Query v5. Pure game rules live in `shared/` and are imported by both the
frontend and the Deno edge functions.

**Spec:** [docs/superpowers/specs/2026-09-02-balance-pass-design.md](../specs/2026-09-02-balance-pass-design.md)
— this plan implements **§6.2** in full. §1.1 (why `KNOWN_GAPS` stays empty),
§5 (orphans), §7.1 (`needsCatalog`) and R-6 (unique registry ids) all bind it,
and §3's other rulings do not touch OW.

**Depends on: Wave 0, merged.** Three things this wave stands on come from it:
`supabase/seed/balance/ow.balance.test.ts` (Task 1 replaces its placeholder),
`poolEligible` in `drawFromPool` (which Brandistock's pool inherits for free),
and `retired: true` on Halberd — **in the very file this wave edits most**.
Branch from a `main` that already has Wave 0, or the first rebase conflicts
inside `OW-Built-in.js`.

## Global Constraints

- **Shell is PowerShell.** No `&&` chaining — use `;` or separate calls.
- **Every commit touching `shared/` must include `npm run functions:sync` output.**
  `supabase/seed/functionSharedSync.test.ts` fails otherwise. This wave edits
  `shared/effects/owEffects.ts`, which is in `game-action`'s manifest — so
  Tasks 1 and 3 both need it. `shared/effects/factionEffects.test.ts` is **not**
  synced (the manifest lists no test files), so a test-only edit produces no
  `supabase/functions` diff.
- **Relative imports inside `shared/` require the `.ts` extension** — Deno runs
  these files verbatim inside edge functions.
- **Run the full suite with `npx vitest run`. NEVER pass `--root`** — it
  silently runs 0 tests.
- **A card's `name` is immutable.** `transform.ts` derives each row's uuid from
  `card:<faction>:<name>`; renaming mints a new id and orphans every deck
  holding the old one. This wave renames nothing — *Brandistock is a new name,
  not a renamed Halberd.*
- **Any edit to `supabase/seed/source/**` requires `npm run seed:build` in the
  same commit**, or `supabase/seed/seedDataSync.test.ts` fails. Adding
  Brandistock moves the count **159 → 160**; after Task 1 every `seed:build` in
  this wave must print `Wrote 160 cards + 7 hero powers`.
- **An effect registration and the seed row that names it belong in ONE
  commit.** A split is red whichever way round it goes: registration-first
  leaves a registered name no seeded card names, which **G4** rejects;
  seed-first leaves a seeded name with no implementation, which **G1** rejects
  and only a forbidden `KNOWN_GAPS` entry would silence. This wave has two such
  pairings and they are Tasks 1 and 2 — see the ⚠ note at the head of each:
  - **Task 1** registers `brandistockOnDeath` *and* seeds the card that names
    it, together.
  - **Task 2** is the mirror image: clearing Bulwark's meta key orphans
    `bulwarkOnPlay`, so the `DELIBERATE_ORPHANS` entry that excuses the orphan
    must land in the same commit as the removal.

  **Tasks 3, 4 and 5 touch no registration** — they are seed data plus, in
  Task 3's case, a comment — so none of them has this shape. **Verify by
  running the full suite, not a targeted file**: `factionEffects.test.ts` alone
  cannot see G1 or G4 at all.
- **`KNOWN_GAPS` must stay EMPTY** (spec §1.1). Brandistock's effect and its
  row land in the same commit, so the card is never seeded unwired — which is
  the only state that would call for an entry. If you find yourself wanting
  one, Task 1 has been split; put it back together rather than adding one.
- **`DELIBERATE_ORPHANS` gains exactly ONE entry: `bulwarkOnPlay`.** Do **not**
  add `halberdOnDeath`. Halberd stays seeded (Wave 0 flags it, it does not
  delete it), so it still names its implementation, G4 stays green, and an
  entry would trip that map's own stale-entry assertion (spec §5).
- **This wave does not touch Halberd.** Its retirement is Wave 0's, its costs
  are unchanged, and its `onDeathEffect` stays `halberdOnDeath`.
- **Public `state.log` must never name a card in a hidden hand.** Brandistock
  draws into a hand; `drawFromPool` already logs anonymously ("adds a card to
  their hand") and this wave adds no log line of its own.
- Report the suite's **before→after passing count** at the end of the wave, not
  "tests pass". On the pre-Wave-0 tree the suite is **1266 passing across 40
  files**; Wave 0 raises that, so **record your own baseline before Task 1**
  rather than reusing this number. This wave is expected to add **+13** tests
  (+6 in `factionEffects.test.ts`, +7 net in `ow.balance.test.ts`).

**Why Rook's patch entry is removed rather than left inert.** `loadSeedData`
applies a patch only when `card.vehicleType == null`, so once the source states
`'airship'` the entry can never fire again. Leaving it would be a second,
silent source of truth for one field — and the paragraph of evidence attached
to it (FtD `BlueprintType 9`, the air-delegate spawn at 200 m, the hull sitting
entirely above the waterline) is *card* reasoning that belongs on the card. The
remaining nine entries stay: those cards still write `VEHICLE_TYPES.ship`, the
lowercase key that evaluates to `undefined`, and this wave is not licensed to
touch them.

**Why the `CATALOG_EFFECTS` assertion is a task step and not a nicety.** Spec
§7.1: `makeCtx` hands every unit test a hand-built catalog, so a missing
`{ needsCatalog: true }` is invisible to the whole suite while `game-action`
runs the effect against an empty catalog and 400s on every real play. Green
suite, dead card. The only check that reads what was actually registered is one
against the derived set, at runtime.

```ts
import { describe, expect, it } from 'vitest'
import { loadSeedData } from '../transform'
import type { SeedCard } from '../../../shared/types'

// The 2026-09-02 balance pass — OW's share, pinned against the seed source.
//
// One file per faction so the five faction branches never edit the same test
// file (spec §2.3). Costs, keywords and card text are plain data that nothing
// else in the suite reads: effectCoverage asks only whether a card's EFFECTS
// are wired, and seedDataSync only whether the generated SQL matches its
// source. Both stay green if a number is fat-fingered. This file would not.
//
// Numbers are spelled out, never derived — a test that recomputes its
// expectation from the source it is checking proves nothing.

async function bySeedKey(): Promise<Map<string, SeedCard>> {
  const { cards } = await loadSeedData()
  return new Map(cards.map((c) => [`${c.faction}:${c.name}`, c]))
}

interface Expected {
  materialCost: number
  blueprintCost: number
  keywords: string[]
  vehicleType: string | null
  cardText: string
}

// Every OW card the pass touched, new or updated. Keywords are compared as
// sets — order in the seed literal is not meaningful. cardText and vehicleType
// are NOT optional here, unlike balancePass.test.ts's shape: this pass moves a
// card's text and a card's type, so leaving either unpinned would leave the
// wave's two least visible edits unguarded.
const CARDS: Record<string, Expected> = {
  'OW:Brandistock': {
    materialCost: 250_000, blueprintCost: 258_000, keywords: ['subScreen'],
    vehicleType: 'ship',
    cardText: 'When this card is destroyed, draw a random GT Airship',
  },
}

describe('2026-09-02 balance pass — OW', () => {
  it.each(Object.entries(CARDS))('%s carries its balanced numbers', async (k, want) => {
    const card = (await bySeedKey()).get(k)
    expect(card, `${k} is missing from the seed source`).toBeDefined()
    expect({
      materialCost: card!.materialCost,
      blueprintCost: card!.blueprintCost,
      keywords: [...(card!.keywords ?? [])].sort(),
      vehicleType: card!.vehicleType ?? null,
      cardText: card!.cardText ?? '',
    }).toEqual({
      materialCost: want.materialCost,
      blueprintCost: want.blueprintCost,
      keywords: [...want.keywords].sort(),
      vehicleType: want.vehicleType,
      cardText: want.cardText,
    })
  })

  // R-6, checked from the DATA end. The engine-side check (that both names are
  // registered) lives in factionEffects.test.ts; this one is what would catch
  // a seed edit that pointed Brandistock at Halberd's id — which compiles,
  // passes G1, and silently rebinds one of the two.
  it('Brandistock names its own death trigger, and Halberd keeps its own', async () => {
    const cards = await bySeedKey()
    expect(cards.get('OW:Brandistock')!.meta?.onDeathEffect).toBe('brandistockOnDeath')
    expect(cards.get('OW:Halberd')!.meta?.onDeathEffect).toBe('halberdOnDeath')
  })
})
```

`bySeedKey` is deliberately duplicated in each faction file rather than shared —
extracting it would put five branches back into one file on every edit, which is
the single thing the split exists to prevent.
